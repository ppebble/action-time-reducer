# 0.4.1 검증 범위

## Lua 소스와 모의 실행

0.4.1에서 `scripts/test.ps1`을 재실행하여 singleplayer 통합 364개, client/server 각각 통합 355개와 모드별 별도 축산 간격 59개, 총 **1,251개**가 통과했습니다.

- 설치된 B42.21 Kahlua VM에서 허용 목록 74개 원본 Lua 클래스 로드.
- 11개 정수 옵션: 기본 0, 범위 0–95, EN/KO 키와 라벨 일치.
- 정확한 클래스만 허용; 미등록·파생·제외 행동 및 설정 누락·비숫자·NaN·무한대 보존.
- 카테고리 독립성, 기본 0, 범위 제한, 반복 조회·재로드의 중복 가속 방지.
- 계산형 getter의 원래 조회 유지와 maxTime getter의 원래값 보존; 금속 바리케이드의 늦은 플래그 회귀 검사.
- 원본 concrete 생성자·완료·취소·유효성 함수 유지. base create는 직접 테이블을 만드는 SP 건축·이동 지원.
- 의료·의복·차량·세탁·도축·독서·유체 원본 getter 표본과 독서 서버 페이지 간격 검사.
- 축산 반복 간격 보정과 필드 복구; 같은 생산량·소모량·XP 및 오류 시 복구 검사.
- 벌목 이벤트 등록 1500 → 1050ms, -1 시간 유지, 원래 타격 핸들러 보존. 자체 애니메이션 노드·변수/XML 문법 검사.
- SP 이동 배치 큐와 중복 가속 방지. MP 이동 및 새 건축의 Lua 시간 보정은 하지 않음.
- 원본 유체 이동·비우기·섭취량 및 흡연 중단·완료 처리 검사.
- 강제완료, 무게·특성·전역시간 조작 및 concrete 생성자 wrapper 없음.

게임 객체를 모의한 단위 증거입니다. XML 검사는 실제 애니메이션 노드 선택·화면 표시·속도 증거가 아닙니다. 클래스 로드는 각 클래스의 모든 콜백·결과를 검증한 것이 아닙니다.

## 수동 클래스 배포 패치

0.4.1은 수동 클래스 복사를 기본 배포로 사용합니다. 이전 agent의 지문 불일치 차단·설치 스크립트 검사는 이 배포의 런타임 보장으로 인용하지 않습니다.

- `scripts/test-manual-server-patch.ps1`에서 현재 배포 클래스에 대한 바이트코드·계산·설정 검사 39개 통과.
- 최종 반환 직전 helper 호출 1개만 추가하는 방식. 원본 필드·시그니처·나머지 메서드 및 거래 패킷은 유지.
- 서버 설정 0/10/30/50/95, 원래 특성 보정 이후 배율, 최소 1ms, 충돌·설정 누락·비정상 값·모드 미활성·클라이언트 상태 검사 대상.
- 클라이언트 및 데디케이트 각각의 내장 Java 25에서 현재 배포 폴더를 클래스 경로 앞쪽에 두고 `-Xverify:all`로 수정 클래스를 로드함. 로드 출처와 helper 위치를 검사하고 agent가 없는지 확인함.
- 같은 클래스 경로를 사용한 자식 Java 프로세스에서도 로드 검사가 통과함. 실제 게임 호스트 부팅 검사는 아님.
- 패치 폴더를 클래스 경로에서 제외하면 각 원본 게임 JAR의 Transaction 클래스를 다시 읽는 검사 통과.
- 배포 manifest의 세 클래스 SHA-256, 전체 Contents의 18개 파일의 스테이징 해시 일치 확인. 설치 프로그램·agent·배치 파일이 없는지 검사.
- 클라이언트·데디케이트 원본 `Transaction.class` SHA-256: `107B0A554CC46D1015398FF283A2E48FAF02EFBC44ADF12854F66394EE2487B6`.
- `Contents/mods/ActionTimeReducer/common/ServerPatch/classes` 배포는 수정한 `Transaction.class`, 자체 `TransferDuration.class`, 자체 `TransferDuration$Access.class`의 정확히 세 파일.
- 원본 JAR을 교체하지 않으며 배포에 agent, PowerShell·배치·실행 파일을 포함하지 않음.
- 게임 업데이트 후 복사본이 남으면 새 원본보다 먼저 로드될 수 있음. 런타임 버전 불일치 안전 차단은 보장하지 않음.

현재 패키지 생성·지문·오프라인 클래스 로드 검사는 서버 실제 부팅·참가자 접속·결과 동기화 증거와 구분합니다. 실제 게임/서버 설치 및 운영 설정은 변경하지 않습니다.

## 알려진 기능 공백

MP 새 건축 배치는 미지원입니다. 멀티 아이템 이동은 운영자가 지원 게임 버전의 세 파일을 수동 설치해야 지원합니다. 다른 `Transaction.class` 교체 모드와 병용하지 않으며, 게임 업데이트 후 새 지원 버전을 확인하고 수동 복사본을 제거·교체해야 합니다. 실제 호스트/두 클라이언트 플레이는 아직 미검증입니다.

## 격리 플레이 테스트 준비 (2026-10-04)

- 사용자 요청으로 전용 캐시·설정·세이브와 로컬 접속 포트 17351/17352를 사용하는 Steam 테스트 서버를 준비함.
- 기존 로컬 모드 0.1.0을 저장소 내부에 백업한 뒤 0.4.1으로 갱신. 13개 로컬 설치 파일의 SHA-256 일치 확인.
- 첫 실제 서버 부팅 성공. 부팅 중 확인한 모드 폴더 누락을 빈 마커 파일 세 개로 보완하고 Lua 1,212개 검사를 재실행하여 통과함.
- 공통 및 42 버전의 애니메이션/액션 검색 폴더가 설치 시 존재하도록 유지함.
- 클래스 패치는 실제 게임 JAR을 교체하지 않고 격리 서버의 클래스 검색 경로에 배포 폴더를 지정해 로드함. 실제 설치 폴더로 복사하는 사용자 절차를 시험한 것은 아님.
- 전체 카테고리 30 설정. 접속·이동시간·취소·아이템 결과는 사용자 플레이 검증 전이며, 게임 내 호스트 및 두 클라이언트 검증도 별도임.

## 0.4.1 싱글 설정 변경 회귀 수정

- 사용자 실게임에서 먹기·아이템 이동에 설정이 반영되지 않았다는 보고를 받음. 기존 단위 검사는 실시간 옵션과 SandboxVars가 다른 상황을 다루지 못했음.
- 설치된 바닐라 샌드박스 편집 UI는 SP에서 SandboxOptions:set으로 옵션을 변경하지만 toLua를 호출하지 않음. 따라서 SandboxVars만 읽으면 이전 값을 사용할 수 있음.
- SP에서는 해당 카테고리의 네이티브 옵션을 직접 읽도록 변경. MP는 기존 서버 동기화 경로 유지.
- 이전 코드에서 새 회귀 검사 실패 확인 후 수정본에서 통과. 실제 원본 음식 생성자 → create → Java 할당 경계 대역 및 실제 이동 생성자·배치 병합 검사 포함.
- 음식 기본 시간 232에 30%를 적용해 162.4, 이동 기본 시간 50/100에 40%를 적용해 30/60이 전달됨. 0으로 변경 시 새 행동은 원래 시간으로 복귀.
- 사용자 요청에 따라 테스트 서버를 정지 확인함. 수정 후 실게임 플레이 성공은 아직 확인되지 않음.

## 사용자 실게임 확인 및 업로드 준비 (2026-10-04)

- 사용자 확인: 0.4.1 싱글에서 시간 단축 반영, 데디케이트 서버에서 시간 단축 반영, 2DW 옷 상자의 바닐라 제작 경로 단축 반영.
- 일반 게임 폴더의 패치 세 파일을 제거하고 원본 Transaction 클래스 로드를 확인함. 테스트 서버는 별도 캐시와 세이브에서 운영함.
- 실제 데디케이트 설치 폴더 java에 패치 세 파일 복사 및 해시·클래스 출처 확인. 게임 내 호스트와 서로 다른 두 클라이언트의 동시 플레이는 아직 미검증.
- 무패치 클라이언트로 재접속한 이후 이동시간 단축 성공을 사용자가 별도로 확인했다는 기록은 아직 없음. 패키지·클래스 검사와 사용자 확인 범위를 구분함.
- 업로드 준비 시 Lua 1,251개와 Java 패치 39개 검사를 재실행해 통과함. 창작마당 공개·업로드는 수행하지 않음.

## 실제 창작마당 업로더 검사

Contents 최상위의 ServerPatch 때문에 게임의 validateContents에서 FolderNotAllowedInContents를 재현했습니다. 수동 패치를 mods/ActionTimeReducer/common/ServerPatch로 이동하고 안내·빌드·배포 경로를 갱신했습니다. 수정된 실제 업로드 폴더는 설치된 B42.21의 validateContents에서 내용·미리보기 검사를 통과했습니다. Steam 생성·제출은 실행하지 않았습니다. 이후 스테이징에서도 같은 검사를 실행합니다.
